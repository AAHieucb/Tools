# Firebase
Envolve là tiền thân của Firebase được gg mua lại. Firebase support:
- Cloud firestore cung real-time database kết nối SSL, phù hợp với ứng dụng vừa và nhỏ vì query phức tạp thì NoSQL sẽ gặp vấn đề.
- Authentication cung cấp pp xác thực qua email, tk google, facebook, password: https://firebase.google.com/docs/auth/web/firebaseui?hl=vi
- Firebase cloud messaging là hệ thống đẩy thông báo tới nh thiết bị khác nhau. VD dùng để xây dựng ứng dụng chat realtime.
- Remote Config giúp cập nhật app nhanh chóng không cần xuất version mới, update data realtime được.
- Firebase hosting web lên CDN phân phối toàn cầu. 
- Cloud function dựng http server như expressjs, có thể trigger xử lý khi db thay đổi, user login hay file uploads, tự động mở rộng thêm máy chủ khi load tăng
- Cloud Storage: lưu tài nguyên như ảnh video vào storage.
- Firebase Dynamic Link tạo link riêng để tối ưu dùng riêng cho các thiết bị Android, iOS.



# Realtime db JSON file cung API
Tạo 1 dự án -> build -> realtime database -> create database -> start in test mode mở bất kỳ ai, start in locked mode (production) là phải cấp quyền -> data -> sửa json -> Mỗi nhánh tạo 1 link đến file json như ở VD thì nhánh One trong Pets có url là /Pets/One.json

Có thể chỉnh quyền ở tab rules, read và write là true hết thì mọi ứng dụng bên ngoài đều có thể chỉnh sửa database của ta -> publish rules
Setup kiểm soát quyền db: vào firebase chỉnh 2 rules là "auth.uid != null" để giới hạn ứng dụng nào được truy câp vào database. Giả sử yêu cầu phải login gg sẽ cần lấy apikey: Project Overview -> Add web app -> Register App -> trong phần Your App npm có trường apikey cần lấy
Trong docs có hướng dẫn, có thể dùng CURL https://firebase.google.com/docs/reference/rest/auth#section-create-email-password -> trong app chỉ cần POST data vào link JSON kèm api key là đc. Data đó có các trường payload json được xđ từ trước như email, password, returnSecureToken -> chuyển sang json post vào link kia
Project firebase -> authentication -> sign-in method -> email/password enabled -> khi có người tham gia vào project sẽ hiện ở mục user, tức user signin vào bằng gmail của họ. Nếu họ tiếp tục signup bằng địa chỉ email đó sẽ báo lỗi vì firebase check trùng. Ở mục user có toàn quyền disable account hay delete account.
Khi người dùng signIn thành công, ta phải xử lý database cho phép người dùng lấy thông tin (authenticated database call), có 2 cách để làm điều này https://firebase.google.com/docs/database/rest/auth: 1 là dùng Google OAuth2, 2 là dùng idToken.
Với C2 trả về 1 tokenId trong response, nếu k sẽ ra error. Rồi parse idToken và nhét vào trường auth của url thì cái url đó sẽ valid với user hiện tại thao tác ok.



# Hosting Firebase
-> Host web tĩnh: free được 1GB
Login firebase -> create project -> chọn cả set up firebase hosting -> continue to console -> build -> hosting -> cd vào thư mục chứa thư mục public của dự án -> npm install -g firebase-tools -> firebae login (làm 1 lần) -> firebase init -> gõ tên thư mục gốc lưu data, để là public thì ấn enter (có sẵn public và index.html)
K chọn github phải có file gốc là index.html, k chọn overwrite cái index.html của ta, k chọn single page -> firebase deploy -> refresh trang

-> Lỗi routing trong ReactJS khi deploy firebase => fix sửa file firebase.json thành:
{
  "hosting": {
    "public": "build",
    "ignore": ["firebase.json", "**/.*", "**/node_modules/**"],
    "rewrites": [
      {
        "source": "**",
        "destination": "/index.html"
      }
    ]
  }
} 
=> Khi chuyển route bị lỗi khi k tìm thấy route đó trong server hosting vì mặc định server chỉ host / or đường dẫn xđ trong package json, vì ta dùng single page nên phải redirect mọi url vào index.html để từ đó chạy các component Switch Route bên trong trỏ đến đúng trang cần lấy (SPA)

-> Connect githubn(hosting CI/CD): Tiếp tục từ npm install -g firebase-tools -> firebase init hosting -> Chọn dùng github và xđ user, repo, nhánh, grant access url, lệnh trước và sau khi deploy -> Có chọn option mỗi khi có merge request sẽ tự động deploy lại.

-> Hosting nextjs web tĩnh. URL: https://tsykin.com/blog/how-to-deploy-nextjs-to-firebase-hosting
Dùng SSG export tĩnh ra trước. Có thể setup CICD.
Nếu web là MPA thì phải dùng dynamic link, vì khi user gõ url vào thẳng trang con thì nó k route được:
{
  "hosting": {
    "public": "out",
    "ignore": [
      "firebase.json",
      "**/.*",
      "**/node_modules/**"
    ],
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "/**", 
        "dynamicLinks": true
      }
    ]
  }
}
export web tĩnh phải sửa config unoptimize: true vì k hỗ trợ.
.gitignore phải xóa /out đi vì phải push cả nó lên git. Khi có git action push lên đúng nhánh sẽ kích hoạt gitaction gắn với firebase chạy deploy.
Mỗi lần sửa đổi: chạy build và export -> push lên git sau khi đổi thư mục out. Check cả 2 url .web.app và .firebaseapp.com thì mới được bản update mới nhất 

-> Hosting React tương tự
K cần vào web firebase tạo sẵn 1 app nx: create a new project (k dùng existing project) -> gõ tên project (là url web hiển thị k viết hoa) -> goi single app hay k tức là có dồn tất cả vào file index.html hay k thì chọn có
Firebase lỗi reload khi reload theo url mới của ứng dụng và fix bằng cách thêm: 
"rewrites": [
  {
    "source": "**",
    "destination": "/index.html"
  }
]
Vì vào bằng 1 url con của react-router-dom thì firebase k chạy app nên k nhận diện được. Đoạn code chỉ là để chạy tiếp vào index.html xử lý DOM và cho ra kết quả
